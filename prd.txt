1. Purpose of This Document
The AI-generated v1.0 of the Doctor Web Portal was built without full alignment to the official MediChain SL design system, PRD requirements, or brand guidelines. This document specifies every update required to bring the existing codebase into full alignment.

This PRD is structured as an UPDATE GUIDE, not a rebuild. It tells the AI developer exactly what to change, what to keep, and what to add — screen by screen, component by component.

4. New Screens to Build

4.1 ScanQR.tsx — Scan Patient QR Code
Route: /scan
Purpose: Doctor uses this to scan a patient's QR code and request access to their records.

Screen Layout (top to bottom):
Page header — 'Scan Patient QR Code' title + subtitle 'Scan the patient QR code or enter their access key manually'
QR Scanner Box — large centered card with a camera viewfinder area (640x480 style box with corner brackets in green). Note: in web app this uses getUserMedia() camera API, not native scanner. Add fallback message if camera permission denied.
OR divider — horizontal rule with 'OR' text centered
Manual Access Key Entry — input field labeled 'Enter One-Time Access Key' with a 6-digit code format hint (e.g. MCH-4829-XK). Submit button 'Request Access' in green.
Recent Scans section — list of last 5 patients scanned this session (from local state only, not persisted). Show patient name, time scanned, access status (Approved/Expired).

On successful scan/key entry: navigate to /patients/:id with the patient data loaded.
On failed/expired key: show red error banner 'Access key expired or invalid. Ask the patient to generate a new one.'

4.2 PatientDetail.tsx — Patient Full Record View
Route: /patients/:id
Purpose: Full view of a patient's record after the doctor has been granted access.

Screen Layout:
Patient Identity Card — top banner with patient name, initials avatar, blood type badge (red), age/gender, patient wallet address (truncated). Green 'Access Granted' badge on the right with expiry time.
Tab navigation — four tabs: Overview | Medical History | Prescriptions | Documents
Overview Tab — show: allergies (red chips, prominently displayed at top), current medications list, last 3 visits summary, next appointment if any
Medical History Tab — timeline of all records from MOCK_RECORDS for this patient. Each record shows date, type icon, description, blockchain hash, verification badge.
Prescriptions Tab — list of all medications with dosage, frequency, prescribing doctor, and date. Add 'Check Interactions' button that shows a mock drug interaction alert if 3+ medications exist.
Documents Tab — show uploaded files (PDFs, X-rays, lab reports) as cards with download icon. Each shows IPFS CID and blockchain verification status.
Sticky bottom bar — 'Upload New Record' (green) + 'Revoke My Access' (outlined red) buttons

Critical: ALWAYS show the allergy section first and in red. This is a patient safety requirement.

4.3 UploadRecord.tsx — Upload Medical Document
Route: /upload or accessible from /patients/:id
Purpose: Doctor uploads a medical document for a patient.

Screen Layout:
Patient selector — searchable dropdown. If arriving from /patients/:id, pre-fill the patient.
Record type selector — dropdown: Lab Report | Prescription | Consultation Note | X-Ray | Surgery Report | Referral Letter | Other
Description field — textarea for the record summary / title
File upload zone — drag-and-drop area using React Dropzone. Accept: PDF, JPG, PNG, DOCX. Max file size: 10MB. Show preview thumbnail for images.
AI Parse toggle — checkbox labeled 'Extract data with AI (recommended)'. When checked, after upload show a parsed summary card with extracted: diagnosis, medications, allergies, key dates.
Upload button — green 'Upload & Store on Blockchain' button. Shows upload progress bar → 'Encrypting' → 'Storing on IPFS' → 'Writing to Blockchain' → 'Complete' steps.
Success confirmation — green success card with record ID, IPFS CID, and blockchain transaction hash (use mock data). Show 'View Record' and 'Upload Another' buttons.

4.4 AccessLog.tsx — Audit Trail
Route: /access-log
Purpose: Full audit log of all patient data access requests and grants the doctor has made.

Screen Layout:
Page header with export button — 'Export as PDF' (secondary button)
Filter bar — filter by patient name, date range (date pickers), status (All / Approved / Pending / Expired / Revoked)
Access log table — columns: Patient | Requested At | Expires At | Record Types | Status | Actions
Status badges — Approved (green), Pending (orange), Expired (grey), Revoked (red)
Action buttons per row — 'Renew' for Expired, 'View Records' for Approved, nothing for Pending
Use MOCK_ACCESS_REQUESTS from mockData.ts as the data source

4.5 Notifications.tsx
Route: /notifications
Screen Layout:
Page header — 'Notifications' + 'Mark All as Read' button
Filter tabs — All | Unread | Records | Appointments | Alerts
Notification list — use MOCK_NOTIFICATIONS from mockData.ts. Each item shows: icon (colored by type), title, message, timestamp, read/unread state (unread has left green border + light green background)
Notification types and their colors: success (green icon), info (blue icon), warning (orange icon), danger (red icon)

4.6 Analytics.tsx
Route: /analytics
Screen Layout:
Summary row — 4 mini stat cards: Total Patients This Month, Records Uploaded This Month, Avg Appointments Per Day, Sync Success Rate
Patient Growth Chart — line chart using Recharts. Data from MOCK_ANALYTICS. X-axis: months (Nov-Apr), Y-axis: patient count. Color: #0D9426
Appointments Chart — bar chart. Same data. Color: #1D9E75
Department Breakdown — horizontal bar list using MOCK_DEPT_STATS. Show department name, percentage bar, and value. Each department has its own color from the mock data.
Records Uploaded Chart — area chart. Data from MOCK_ANALYTICS.records field. Color: #0C2340
